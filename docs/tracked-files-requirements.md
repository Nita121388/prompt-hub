# 跟踪文件与版本归档 - 需求说明

## 1. 背景

用户长期在同一个 Markdown/文本文件里记录需求、问题、Prompt，难以按天对比变化。希望通过 Git 保存历史版本，并能一键生成“下一份”文件，实现日常归档。

## 2. 目标

- 支持指定任意本地文件为“跟踪文件”（可在任意目录）
- 支持右键一键生成“下一份文件”，文件名可配置，默认“日期 + 版本号”
- 跟踪文件保存后自动同步到远程仓库
- 删除跟踪文件时提示是否同步删除远端归档
- 复用现有 Git 远端配置，不新增远端，只在仓库内分目录存放归档
- 在 VS Code 内标记被跟踪的文件

## 3. 非目标

- 不提供完整 Git 管理 UI（仍使用现有 Git 同步逻辑）
- 不处理跨设备冲突自动合并（继续沿用现有 Git 冲突提示）
- 不要求系统级文件标记（仅 VS Code 内标记）

## 4. 用户故事

1. 我可以在任意目录选择一个文件开始跟踪。
2. 我在文件里持续记录，当我保存时会自动同步到远端。
3. 我右键“下一份”，会在同目录生成新文件并继续跟踪。
4. 我删除跟踪文件时，会询问是否删除远端归档。
5. 我可以在 VS Code 内看到“该文件已被跟踪”的标记。

## 5. 功能需求

### FR1 远程仓库与归档目录

- 复用 `otter.git.remoteUrl` 与 `otter.storagePath`
- 归档存放在 `storagePath` 下可配置的子目录（默认 `.otter-tracked/`）

### FR2 跟踪任意文件

- 支持通过命令或右键选择任意文件开始跟踪
- 跟踪时应创建归档目录与索引元数据

### FR3 一键“下一份”

- 右键或命令触发“下一份”逻辑
- 新文件生成在“当前文件同目录”
- 文件名模板可配置，默认 `{date}-{index}{ext}`（同日多版本用 index 递增）
- 触发后自动开始跟踪新文件

### FR4 自动同步

- 跟踪文件保存后自动更新归档文件
- 自动提交并推送（复用现有 `GitSyncService`）
- 支持可配置的延迟防抖

### FR5 删除提示

- 检测到跟踪文件被删除时，提示是否删除远端归档文件
- 无论是否删除远端，均停止跟踪该文件

### FR6 标记

- 在 VS Code 内对跟踪文件显示标记（徽标/提示）

## 6. 配置项（建议）

- `otter.track.baseDir`：归档目录（相对 `storagePath`）
- `otter.track.filenameTemplate`：文件名模板（默认 `{date}-{index}{ext}`）
- `otter.track.dateFormat`：日期格式（默认 `YYYY-MM-DD`）
- `otter.track.indexPadding`：版本号补零长度（默认 2）
- `otter.track.autoSyncOnSave`：保存后自动同步（默认 true）
- `otter.track.autoSyncDelaySeconds`：自动同步延迟（默认 30）

## 7. 交互与提示

- 跟踪成功：提示归档目录与当前跟踪文件
- 生成下一份成功：提示新文件路径并打开
- 删除触发：弹窗询问“是否删除远端归档”

## 8. 验收标准

- 可以对任意文本文件执行“开始跟踪”
- 保存后远端仓库内出现对应归档文件
- “下一份”能生成新文件且自动跟踪
- 删除文件时必有确认提示
- VS Code 内可看到跟踪标记
